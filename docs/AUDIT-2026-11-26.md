# Audit fonctionnel et UX — 26 novembre 2026

Version contrôlée : 0.0.1. Ce document complète le bilan du 22 novembre et décrit les vérifications du lot de reprise.

## Corrections livrées

- Les rôles délégués voient uniquement les rubriques Pages, Articles et Événements correspondant à leurs droits et aux dépendances disponibles. Un lien direct vers une rubrique masquée revient à l’accueil ; les vérifications des mutations restent côté serveur.
- Les commandes de création de liste et de progression dans une newsletter respectent la préférence de réduction des animations.
- Les utilitaires JavaScript de traduction et de défilement restent privés, mais sont accessibles à tous les gestionnaires du fichier. Cela corrige les erreurs qui pouvaient interrompre le retour « Copié ! » et la progression vers la rédaction d’une newsletter.
- Les commandes « Tout sélectionner » et « Tout désélectionner » utilisent un gestionnaire unique dans l’assistant et les réglages. Elles respectent le groupe ciblé et ne modifient pas les cases désactivées.
- Le champ temporaire utilisé par la copie de secours est supprimé même lorsque le navigateur refuse la copie. La sélection manuelle du code reste possible.
- Le README décrit la version et les parcours réellement présents, ainsi que les dépendances optionnelles.

## Vérifications réalisées

Tous les **29 fichiers PHP** passent le contrôle syntaxique avec PHP 8.4.27. Le script d’administration passe `node --check`.

Les **15 commandes de test** du workflow passent : permissions et historique, ACF et constructeurs, médias, newsletters, WooCommerce, restrictions par type de contenu, régressions de délégation, première installation, réglages, trois scénarios de navigation PHP, navigation tactile/clavier, sous-menus mobiles et actions JavaScript.

Le nouveau test `tests/admin-actions.js` charge le fichier JavaScript complet. Il vérifie le passage du choix de modèle à la rédaction, le focus du sujet, la réduction des animations, la copie native et de secours, le message traduit, le nettoyage après échec et les commandes de sélection par groupe.

Le parcours réel suivant a également été exécuté dans un WordPress **7.1.5 isolé**, avec PHP 8.4.27 et Chromium, à une largeur de **390 pixels** :

1. Un rôle délégué autorisé à modifier les pages ouvre l’éditeur. Les rubriques Articles et Événements sont absentes.
2. Il modifie le titre d’une page et enregistre sa proposition.
3. Un visiteur voit toujours l’ancien titre tant que la proposition attend sa validation.
4. L’administrateur approuve la proposition.
5. Le visiteur voit alors le nouveau titre.

La capture mobile a été contrôlée visuellement : le champ, la navigation et les boutons de blocs restent lisibles dans la largeur de l’écran.

## Portée des résultats

Les contrats WooCommerce, ACF et newsletters sont vérifiés par les tests isolés livrés avec le projet. Ce lot ne remplace pas un essai avec les versions exactes de WooCommerce, The Events Calendar, ACF et des constructeurs installés sur chaque site. Aucun email n’a été expédié, aucune commande de boutique n’a été modifiée et aucune soumission à WordPress.org n’a été effectuée pendant ces contrôles.

L’archive installable reprend la structure du workflow : le fichier principal, `readme.txt`, la licence, `includes/`, `assets/` et `languages/`, sous un seul dossier `dendrila-simple-edit/`. Les tests et la documentation de développement ne sont pas inclus dans le ZIP.
