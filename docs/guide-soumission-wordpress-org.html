Ta progression

0 étape cochée
La progression est conservée sur ton appareil quand le navigateur le permet. Rien n’est envoyé à un serveur.

1. Mon compte WordPress.org

Utilise le bouton « Me connecter » ci-dessus. Si tu n’as pas de compte, choisis « Créer mon compte ». Confirme ton adresse e-mail si WordPress.org le demande.

Adresse : wordpress.org/plugins/developers/add/. Une fois connecté, c’est directement le bon formulaire. Tu n’as aucun statut développeur à demander à l’avance.

Pour un auteur d’extension, WordPress.org demande la 2FA. Ouvrir les réglages de sécurité du compte ↗. Conserve les codes de secours.

2. Préparer le fichier à déposer

Tu dois soumettre le ZIP complet du plugin, pas une capture d’écran, ni son dépôt GitHub.

Vérification utile : le readme.txt de l’archive indique actuellement Contributors: juliane16. Vérifie que cet identifiant est bien un compte WordPress.org devant être crédité. S’il ne correspond pas au véritable contributeur, corrige-le avant le dépôt.

Important pour Dendrila Simple Edit : la migration du mailing doit conserver les désinscriptions. N’utilise pas de vrais contacts pour un premier test.

Création et publication de produits, rôles, listes de diffusion, désinscription, assistant initial et formulaires sur mobile. C’est distinct de la démarche de publication sur WordPress.org.

Contrôle le nom Dendrila Simple Edit, la version 0.0.1, la licence, les dépendances et le fichier readme.txt.

Afficher et copier le contenu actuel du readme.txt

Si tu veux vérifier le readme dans le validateur officiel sans le chercher dans le ZIP, copie ce texte.

3. Contrôles officiels — sans installer un nouveau plugin

Aucune installation supplémentaire n’est nécessaire pour accéder au formulaire de soumission. Le validateur de readme.txt fonctionne en ligne.

Vérifier le readme.txt en ligne ↗Lire les règles WordPress.org ↗Revenir au formulaire de dépôt ↗FAQ des auteurs ↗

Colle le contenu du readme dans le formulaire, lance la validation et lis les erreurs éventuelles.

Si le fichier est modifié, cette modification doit aussi se retrouver dans le ZIP qui sera soumis : copier un readme corrigé ici ne modifie pas l’archive.

Et « Plugin Check », alors ?

Ce n’est pas un « mode développeur ». Plugin Check est un outil d’analyse du code, distinct du formulaire de publication. Tu n’es pas obligé d’installer une nouvelle extension juste pour accéder au dépôt.

Sur ton laboratoire, Plugin Check était déjà présent lors du dernier contrôle. Si tu veux t’en servir sans rien installer, va dans Outils → Plugin Check sur ton WordPress de test. Sinon, continue vers le dépôt ; WordPress.org effectue sa propre revue après soumission. Ne considère toutefois pas cela comme un remplacement complet des tests de sécurité.

La revue WordPress.org contrôle notamment la sécurité, les autorisations, les données et les règles du répertoire. Une vérification du readme ne valide pas le code.

4. Déposer Dendrila Simple Edit

Ouvrir le formulaire officiel de soumission ↗

Si WordPress.org te demande de te reconnecter, reconnecte-toi puis recharge le lien direct. Tu n’as pas besoin de passer par l’administration d’un de tes sites WordPress.

Choisis l’archive complète, conserve le nom de l’extension et contrôle les informations affichées avant l’envoi.

Le dépôt est alors en attente de vérification par WordPress.org. Cela ne veut pas encore dire que ton plugin est publié.

Vérifie les messages de plugins@wordpress.org. En cas de demande de correction, réponds au fil reçu, sans créer un nouveau dépôt.

5. Une fois le plugin approuvé

Ce n’est qu’après l’accord de WordPress.org qu’un dépôt de publication Subversion (SVN) est attribué. GitHub et SVN ne sont pas le même dépôt.

WordPress.org t’envoie les indications utiles par e-mail.

Les sources vont dans trunk/, les versions stables dans tags/, les visuels de la fiche dans assets/.

Vérifie le texte, les images, la licence, les liens, puis installe la version publique sur un site de test.
